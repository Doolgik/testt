# WhatsApp → AI-бот → Bitrix24

Автоматизация для CRM: клиенту в WhatsApp отвечает AI-бот, консультирует по
вашей базе знаний, **сам двигает сделку по воронке Bitrix** в зависимости от
готовности клиента купить, и **переводит сложные диалоги на живого оператора**.

Без n8n и визуальных конструкторов — это обычный сервис на Python (FastAPI),
который запускается одной командой через Docker.

---

## Что умеет бот

1. **Консультирует** клиента в WhatsApp на основе вашей базы знаний (папка
   `knowledge_base/`). Чего нет в базе — не выдумывает.
2. **Квалифицирует лида** и автоматически меняет стадию сделки в Bitrix:
   - `Интересуется` — клиент просто спрашивает, сравнивает, думает;
   - `Почти готов` — спрашивает про оплату/сроки/КП, греется;
   - `Готов купить` — согласен оформлять.
3. **Переводит на оператора** (на вас), когда не может помочь по базе знаний,
   нужен индивидуальный расчёт, клиент просит человека или готов к покупке.
   После перевода бот замолкает по этому диалогу, а вы получаете уведомление
   в WhatsApp + комментарий в сделке Bitrix.
4. **Создаёт контакт и сделку** в Bitrix при первом обращении клиента.

## Архитектура (как это устроено)

```
Клиент в WhatsApp
        │  сообщение
        ▼
WhatsApp Cloud API (Meta)
        │  webhook (POST)
        ▼
┌─────────────────────────────────────────┐
│  Этот сервис (FastAPI)                   │
│  app/main.py      — приём вебхуков       │
│  app/handler.py   — оркестрация          │
│  app/agent.py     — бот на Claude        │
│  app/knowledge_base.py — база знаний     │
│  app/bitrix.py    — клиент Bitrix24      │
│  app/whatsapp.py  — клиент WhatsApp      │
│  app/conversation.py — память (SQLite)   │
└─────────────────────────────────────────┘
        │  ответ клиенту        │  CRM-действия
        ▼                       ▼
   WhatsApp                  Bitrix24
```

Модель (Claude) на каждом сообщении решает: что ответить, менять ли стадию
(инструмент `update_lead_stage`), звать ли оператора (`handoff_to_operator`).
Сами действия в CRM/WhatsApp выполняет `handler.py`.

## Быстрый старт (локально)

```bash
# 1. Зависимости
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# 2. Настройки
cp .env.example .env
#   открой .env и впиши ключи (см. разделы ниже)

# 3. Заполни базу знаний (папка knowledge_base/, файлы .md)

# 4. Запуск
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Через Docker:

```bash
cp .env.example .env   # заполни
docker compose up -d --build
```

Проверка, что живой: открой `http://localhost:8000/` — увидишь, какие
интеграции уже настроены.

## Настройка по шагам

### Шаг 1. Ключ Anthropic (мозг бота)

1. Зарегистрируйся на <https://console.anthropic.com/>.
2. **API Keys** → создай ключ → впиши в `.env` как `ANTHROPIC_API_KEY`.
3. Пополни баланс (бот платный по токенам). Для большого потока сообщений
   можно поставить более дешёвую модель: `ANTHROPIC_MODEL=claude-sonnet-4-6`.

### Шаг 2. WhatsApp Cloud API (Meta)

> Бот использует **официальный** API — без риска банов, но нужен бизнес-аккаунт.

1. Зайди в <https://developers.facebook.com/> → создай приложение типа
   **Business**.
2. Добавь продукт **WhatsApp**.
3. В разделе **WhatsApp → API Setup**:
   - скопируй **Phone number ID** → `.env` `WA_PHONE_NUMBER_ID`;
   - для теста дадут временный токен (24 ч). Для прода создай **постоянный**
     токен через System User (Business Settings → Users → System Users →
     Generate token с правами `whatsapp_business_messaging`) → `.env`
     `WA_ACCESS_TOKEN`.
4. Придумай любую строку для `WA_VERIFY_TOKEN` (например, `my-secret-123`).
5. Подключи вебхук (см. Шаг 4).

### Шаг 3. Bitrix24

> Можно подключить позже. Без Bitrix бот будет просто консультировать.

1. В Bitrix24: **Разработчикам → Другое → Входящий вебхук**.
2. Дай права на **CRM** (`crm`).
3. Скопируй URL вида `https://ВАШ-ПОРТАЛ.bitrix24.ru/rest/1/ТОКЕН/` → `.env`
   `BITRIX_WEBHOOK_URL`.
4. Настрой воронку и стадии под себя:
   - по умолчанию бот мапит стадии на `NEW` → `PREPARATION` → `EXECUTING`
     основной воронки;
   - если у тебя своя воронка / свои стадии — открой `app/bitrix.py` и
     поправь словарь `STAGE_MAP` (узнать STAGE_ID можно методом
     `crm.dealcategory.stage.list` или в настройках воронки);
   - если используешь дополнительную воронку — укажи её ID в
     `BITRIX_CATEGORY_ID`, префикс `C{ID}:` к стадиям добавится сам.
5. `BITRIX_ASSIGNED_USER_ID` — ID менеджера, на которого вешать сделки.

### Шаг 4. Подключить вебхук WhatsApp к сервису

Сервис должен быть доступен из интернета по HTTPS. Варианты:
- **Прод:** разверни на VPS за HTTPS (nginx + сертификат, или туннель).
- **Тест:** прокинь туннель, например `ngrok http 8000` или
  `cloudflared tunnel`.

Затем в Meta (**WhatsApp → Configuration → Webhook**):
- **Callback URL:** `https://ТВОЙ-ДОМЕН/webhook/whatsapp`
- **Verify token:** та же строка, что в `WA_VERIFY_TOKEN`
- Нажми **Verify and Save** (сервис ответит на проверочный GET).
- Подпишись на поле **messages**.

Готово. Напиши боту в WhatsApp — он ответит.

## Идеи для развития (что ещё можно допилить)

- **Поддержка картинок/голоса:** распознавать фото (Claude умеет vision) и
  голосовые (через транскрибацию) — сейчас бот просит написать текстом.
- **Часы работы:** вне графика — отвечать «мы офлайн, ответим утром» и не
  дёргать оператора.
- **Антиспам / лимиты:** ограничение частоты сообщений от одного номера.
- **Аналитика:** дашборд по стадиям, конверсии, времени ответа.
- **Передача обратно боту:** команда оператора «верни боту» (снять `handoff`).
- **Несколько каналов:** добавить Telegram/Avito по той же схеме (общий
  `handler.py`, разные адаптеры каналов).
- **Масштабирование базы знаний:** если документов станут сотни страниц —
  подключить RAG (эмбеддинги + векторный поиск) вместо подстановки всей базы
  в промпт. Точка расширения — `app/knowledge_base.py`.
- **Постгрес/Redis** вместо SQLite при большом потоке диалогов.

```
  config.py          настройки из .env

  knowledge_base.py  загрузка базы знаний
  prompts.py         системный промпт бота
  agent.py           AI-бот на Claude + инструменты (tool use)
  conversation.py    история диалогов и состояние (SQLite)
  handler.py         оркестрация обработки сообщения
knowledge_base/      ваши документы (.md)
tests/               тесты логики
Dockerfile, docker-compose.yml
.env.example
```
